# MT5Service — Account Methods (Mid-Level API)

> 4 convenient methods for reading account state — a composed snapshot, plus direct typed property reads — without protobuf ceremony.

**🧩 API Layer:** **MID-LEVEL** — a friendly facade over [`MT5Account`](../MT5Account/1.%20Account_information/Account_Information.Overview.md) that returns plain JS types and typed objects.

**Implementation:** these methods live in `src/MT5Service.ts`, wrapping the low-level `accountSummary` / `accountInfo{Double,Integer,String}` calls on `MT5Account`.

**Demos:** `examples/demos/service/04_service_demo.js` · `examples/demos/run_all.js`.

[← MT5Service Overview](./MT5Service.Overview.md) · [low-level group ↓](../MT5Account/1.%20Account_information/Account_Information.Overview.md)

## 🎯 Why these methods exist

**Problem** — on `MT5Account`, a single-property read returns a protobuf `*Data` object you must unwrap, and the property enum must be looked up:

```ts
// Low-level (MT5Account)
import { AccountInformationPb } from '@metarpc/nodemt5';
const balance = await account.accountInfoDouble(
  AccountInformationPb.AccountInfoDoublePropertyType.ACCOUNT_BALANCE,
); // already a number here, but you still carry the enum import everywhere
```

**Solution** — `MT5Service` composes the whole account into one typed object, and still exposes the single-property reads when you need just one value:

```ts
// Mid-level (MT5Service)
const a = await service.getAccountSummary();
console.log(a.balance, a.equity, a.currency); // ✅ plain fields, no enums
```

**Advantages**

- ✅ One call → the whole account as a typed `AccountInfo` object.
- ✅ Plain JS types (`number` / `string`) — no `.getXxx()` chains.
- ✅ `tradeMode` decoded to `'DEMO' | 'CONTEST' | 'REAL'`, plus the raw `tradeModeCode`.
- ✅ Server time already converted to seconds-since-epoch, with the UTC shift for building history windows.

## 📋 All 4 methods

| Method | Returns | Low-level equivalent |
|--------|---------|----------------------|
| **`getAccountSummary()`** | `Promise<AccountInfo>` | `accountSummary()` + margin doubles, composed |
| **`getAccountDouble(propertyId)`** | `Promise<number>` | `accountInfoDouble(propertyId)` |
| **`getAccountInteger(propertyId)`** | `Promise<number>` | `accountInfoInteger(propertyId)` |
| **`getAccountString(propertyId)`** | `Promise<string>` | `accountInfoString(propertyId)` |

## 📦 `AccountInfo` (DTO)

Returned by `getAccountSummary()`:

| Field | Type | Description |
| ----- | ---- | ----------- |
| `login` | `number` | Account number. |
| `currency` | `string` | Deposit currency (USD, EUR, …). |
| `balance` | `number` | Balance (without floating P&L). |
| `equity` | `number` | Equity (balance + floating P&L). |
| `credit` | `number` | Credit. |
| `margin` | `number` | Used margin. |
| `freeMargin` | `number` | Free margin. |
| `marginLevel` | `number` | Margin level, %. |
| `leverage` | `number` | Leverage (100 = 1:100). |
| `name` | `string` | Account holder. |
| `company` | `string` | Broker name. |
| `server` | `string` | Trade server (e.g. `MetaQuotes-Demo`). |
| `tradeMode` | `'DEMO' \| 'CONTEST' \| 'REAL' \| 'UNKNOWN'` | Decoded account type. |
| `tradeModeCode` | `number` | Raw trade-mode enum value. |
| `serverTime` | `number` | Broker server time — **seconds** since epoch. |
| `utcServerShiftMinutes` | `number` | `serverTime = utc + shift·60`. Use it to build server-time history windows. |

> `serverTime` is the broker's wall clock; subtract `utcServerShiftMinutes·60` to get real UTC. The [history methods](./3.%20Position_Orders_Methods.md) accept a `Date` directly and do this for you.

## 📖 Method details

### 1) `getAccountSummary(): Promise<AccountInfo>`

Everything about the account in one round-trip. Composes `accountSummary` with the margin/level fields and decodes the trade-mode enum.

```ts
const a = await service.getAccountSummary();
console.log(`${a.name} #${a.login} on ${a.server}`);
console.log(`Balance ${a.balance} ${a.currency} · Equity ${a.equity} · Free ${a.freeMargin}`);
```

### 2) `getAccountDouble(propertyId): Promise<number>`

One numeric property, already unwrapped. Pass an `AccountInfoDoublePropertyType`:

`ACCOUNT_BALANCE` · `ACCOUNT_CREDIT` · `ACCOUNT_PROFIT` · `ACCOUNT_EQUITY` · `ACCOUNT_MARGIN` · `ACCOUNT_MARGIN_FREE` · `ACCOUNT_MARGIN_LEVEL` · `ACCOUNT_MARGIN_SO_CALL` · `ACCOUNT_MARGIN_SO_SO` · `ACCOUNT_MARGIN_INITIAL` · `ACCOUNT_MARGIN_MAINTENANCE` · `ACCOUNT_ASSETS` · `ACCOUNT_LIABILITIES` · `ACCOUNT_COMMISSION_BLOCKED` (14 total).

```ts
import { AccountInformationPb } from '@metarpc/nodemt5';
const D = AccountInformationPb.AccountInfoDoublePropertyType;
const profit = await service.getAccountDouble(D.ACCOUNT_PROFIT);
```

### 3) `getAccountInteger(propertyId): Promise<number>`

One integer property. Pass an `AccountInfoIntegerPropertyType`:

`ACCOUNT_LOGIN` · `ACCOUNT_TRADE_MODE` · `ACCOUNT_LEVERAGE` · `ACCOUNT_LIMIT_ORDERS` · `ACCOUNT_MARGIN_SO_MODE` · `ACCOUNT_TRADE_ALLOWED` · `ACCOUNT_TRADE_EXPERT` · `ACCOUNT_MARGIN_MODE` · `ACCOUNT_CURRENCY_DIGITS` · `ACCOUNT_FIFO_CLOSE` · `ACCOUNT_HEDGE_ALLOWED` (11 total).

```ts
const I = AccountInformationPb.AccountInfoIntegerPropertyType;
const leverage = await service.getAccountInteger(I.ACCOUNT_LEVERAGE);
```

### 4) `getAccountString(propertyId): Promise<string>`

One string property. Pass an `AccountInfoStringPropertyType`:

`ACCOUNT_CURRENCY` · `ACCOUNT_COMPANY` · `ACCOUNT_NAME` · `ACCOUNT_SERVER` (4 total).

```ts
const S = AccountInformationPb.AccountInfoStringPropertyType;
const server = await service.getAccountString(S.ACCOUNT_SERVER);
```

## 💡 Usage examples

### 1) Balance and equity — 6 lines → 2

```ts
// ❌ BEFORE (low-level) — unwrap each read
import { AccountInformationPb } from '@metarpc/nodemt5';
const D = AccountInformationPb.AccountInfoDoublePropertyType;
const balance0 = await account.accountInfoDouble(D.ACCOUNT_BALANCE);
const equity0  = await account.accountInfoDouble(D.ACCOUNT_EQUITY);

// ✅ AFTER (mid-level) — one object
const a = await service.getAccountSummary();
console.log(`Balance: ${a.balance}, Equity: ${a.equity}`);
```

### 2) Margin level from the summary

```ts
const a = await service.getAccountSummary();
const level = a.margin > 0 ? (a.equity / a.margin) * 100 : Infinity;
console.log(`Margin level: ${level.toFixed(2)}%`);
```

### 3) Demo vs real guard

```ts
const a = await service.getAccountSummary();
if (a.tradeMode === 'DEMO')      console.log('✅ Demo — safe for testing');
else if (a.tradeMode === 'REAL') console.log('🚨 REAL account — live money!');
```

### 4) Dashboard line

```ts
const a = await service.getAccountSummary();
console.log(
  `Account ${a.login} · ${a.company} · 1:${a.leverage}\n` +
  `Balance ${a.balance.toFixed(2)} ${a.currency} · Equity ${a.equity.toFixed(2)} · Free ${a.freeMargin.toFixed(2)}`,
);
```

### 5) Balance monitor

```ts
import { AccountInformationPb } from '@metarpc/nodemt5';
const D = AccountInformationPb.AccountInfoDoublePropertyType;

const timer = setInterval(async () => {
  try {
    const balance = await service.getAccountDouble(D.ACCOUNT_BALANCE);
    console.log(`[${new Date().toLocaleTimeString()}] Balance: ${balance.toFixed(2)}`);
  } catch (e) {
    console.error('monitor error:', (e as Error).message);
  }
}, 5000);
// later: clearInterval(timer);
```

### 6) Affordability check before trading

```ts
import { AccountInformationPb } from '@metarpc/nodemt5';
const D = AccountInformationPb.AccountInfoDoublePropertyType;

async function canOpen(requiredMargin: number): Promise<boolean> {
  const free = await service.getAccountDouble(D.ACCOUNT_MARGIN_FREE);
  if (free < requiredMargin) {
    console.warn(`⚠️ Insufficient margin: ${free.toFixed(2)} (need ${requiredMargin.toFixed(2)})`);
    return false;
  }
  return true;
}
```

## 🔧 When to use which

- **Need several properties / a dashboard / a report** → `getAccountSummary()` (already has everything).
- **Need exactly one value, or a repeated poll** → `getAccountDouble / Integer / String`.
- **Need something the summary doesn't carry** (e.g. `ACCOUNT_PROFIT`, SO levels, assets) → `getAccountDouble(...)`.

## 🎯 Summary

The Account methods remove protobuf ceremony: no manual requests, no `.getXxx()` chains, no enum imports for the common path. You get plain JS types and a single composed `AccountInfo` object that reads like ordinary code.
