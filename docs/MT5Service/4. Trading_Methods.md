# MT5Service — Trading Methods (Mid-Level API)

> Place, modify, close, validate and size trades with plain argument objects and string order actions — no protobuf, no enum imports.

**🧩 API Layer:** **MID-LEVEL** — a facade over the low-level [Trading Operations](../MT5Account/4.%20Trading_Operations/Trading_Operations.Overview.md) group.

**Implementation:** `src/MT5Service.ts`. **Demos:** `examples/demos/service/04_service_demo.js`.

[← MT5Service Overview](./MT5Service.Overview.md) · [low-level group ↓](../MT5Account/4.%20Trading_Operations/Trading_Operations.Overview.md)

## 🎯 Why these methods exist

On `MT5Account`, sending an order means building a protobuf request, setting the operation enum, and each optional field by setter:

```ts
// Low-level
import { TradingHelperPb } from '@metarpc/nodemt5';
const req = new TradingHelperPb.OrderSendRequest();
req.setSymbol('EURUSD');
req.setOperation(TradingHelperPb.TMT5_ENUM_ORDER_TYPE.TMT5_ORDER_TYPE_BUY);
req.setVolume(0.1);
req.setStopLoss(1.08);
const d = await account.orderSend(req);
if (d.getReturnedCode() === 10009) { /* … */ }
```

`MT5Service` takes a plain object with a **string** `action` and returns a typed `OrderResult`:

```ts
// Mid-level
const r = await service.placeOrder({ symbol: 'EURUSD', action: 'BUY', volume: 0.1, stopLoss: 1.08 });
if (r.retcode === 10009) console.log('filled, ticket', r.ticket);
```

---

## 🛑 The trade retcode

MT5 trades carry a **trade-server return code**. **`10009` = DONE (success).** `placeOrder` / `modifyOrder` / `closeOrder` **reject the promise** only on an API/transport error; a **broker rejection comes back in the result** as a non-`10009` `retcode`. Always check it.

Common codes: `10009` DONE · `10004` REQUOTE · `10006` REJECTED · `10013` INVALID · `10014` INVALID_VOLUME · `10015` INVALID_PRICE · `10016` INVALID_STOPS · `10018` MARKET_CLOSED · `10019` NO_MONEY. See [Return Codes](../All_Guides/RETURN_CODES_REFERENCE.md).

## 📋 All methods

| Method | Returns | Purpose |
|--------|---------|---------|
| **`placeOrder(req: OrderRequest)`** | `Promise<OrderResult>` | Send a market or pending order. |
| **`modifyOrder(req: ModifyRequest)`** | `Promise<OrderResult>` | Change SL/TP (and price/expiration for pendings). |
| **`closeOrder(req: CloseRequest)`** | `Promise<CloseResult>` | Close a position (full/partial) or delete a pending. |
| **`checkOrder(req)`** | `Promise<OrderCheckResult>` | Validate before sending (margin, free margin after deal…). |
| **`calculateMargin(action, symbol, volume, price)`** | `Promise<number>` | Required margin for a prospective order. |
| **`calculateProfit(action, symbol, volume, openPrice, closePrice)`** | `Promise<number>` | Profit of a prospective trade. |

**`action: OrderAction`** is one of `'BUY'` · `'SELL'` · `'BUY_LIMIT'` · `'SELL_LIMIT'` · `'BUY_STOP'` · `'SELL_STOP'` · `'BUY_STOP_LIMIT'` · `'SELL_STOP_LIMIT'`.

## 📦 DTOs

### `OrderRequest` (→ `placeOrder`)

| Field | Type | Notes |
| ----- | ---- | ----- |
| `symbol` | `string` | Instrument. **required** |
| `action` | `OrderAction` | Order type (string). **required** |
| `volume` | `number` | Lots. **required** |
| `price?` | `number` | Entry price (pending; market uses the live quote). |
| `stopLoss?` / `takeProfit?` | `number` | Protective levels. |
| `slippage?` | `number` | Max deviation (points). |
| `comment?` | `string` | Free-text tag. |
| `magic?` | `number` | Expert id — needed for per-strategy filtering. |
| `stopLimitPrice?` | `number` | For stop-limit orders. |
| `expirationTimeType?` / `expirationTime?` | `number` / `Date` | Pending-order expiry. |
| `quotesWaitMs?` | `number` | How long to wait for the first quote (default 5000). |

### `OrderResult` (← `placeOrder` / `modifyOrder`)

`ticket` (= position ticket for a filled market order) · `retcode` · `retcodeDescription` · `deal` · `order` · `volume` · `price` · `bid` · `ask` · `comment` · `requestId`.

### `ModifyRequest` — `ticket` (required) · `stopLoss?` · `takeProfit?` · `price?` · `stopLimit?` · `expirationTimeType?` · `expirationTime?`.

### `CloseRequest` — `ticket` (required) · `volume?` (omit / 0 = full close) · `slippage?`. → **`CloseResult`**: `retcode` · `retcodeDescription` · `closeMode`.

### `OrderCheckResult` (← `checkOrder`)

`returnedCode` (**0 = would be accepted**) · `balance` · `equity` · `profit` · `margin` · `marginFree` · `marginLevel` · `comment`.

## 📖 Method details

```ts
// Market BUY with SL/TP
const r = await service.placeOrder({ symbol: 'EURUSD', action: 'BUY', volume: 0.1, stopLoss: 1.08, takeProfit: 1.09 });

// Modify SL/TP
await service.modifyOrder({ ticket: r.ticket, stopLoss: 1.082, takeProfit: 1.095 });

// Close (full)
const c = await service.closeOrder({ ticket: r.ticket });

// Validate first (0 = ok)
const chk = await service.checkOrder({ symbol: 'EURUSD', action: 'BUY', volume: 0.1 });

// Sizing calculators
const margin = await service.calculateMargin('BUY', 'EURUSD', 1.0, 1.085);
const profit = await service.calculateProfit('BUY', 'EURUSD', 0.1, 1.085, 1.090);
```

## 💡 Usage examples

### 1) Place and confirm

```ts
const r = await service.placeOrder({ symbol: 'EURUSD', action: 'BUY', volume: 0.1 });
if (r.retcode === 10009) console.log(`✅ Filled, ticket #${r.ticket} @ ${r.price}`);
else console.log(`❌ Rejected: ${r.retcodeDescription} (code ${r.retcode})`);
```

### 2) Affordability before sending

```ts
const margin = await service.calculateMargin('BUY', 'EURUSD', 1.0, (await service.getSymbolTick('EURUSD')).ask);
const a = await service.getAccountSummary();
console.log(margin <= a.freeMargin ? '✅ affordable' : `❌ need ${margin.toFixed(2)}, free ${a.freeMargin.toFixed(2)}`);
```

### 3) Validate → send

```ts
const chk = await service.checkOrder({ symbol: 'EURUSD', action: 'BUY', volume: 0.1 });
if (chk.returnedCode !== 0) throw new Error(`check failed: ${chk.comment}`);
const r = await service.placeOrder({ symbol: 'EURUSD', action: 'BUY', volume: 0.1 });
```

### 4) Partial close (half)

```ts
const { positions } = await service.getOpenedOrders();
const p = positions[0];
if (p) await service.closeOrder({ ticket: p.ticket, volume: p.volume / 2 });
```

### 5) Move stop to break-even

```ts
const { positions } = await service.getOpenedOrders();
for (const p of positions) {
  if (p.type === 0 && p.priceCurrent > p.priceOpen) { // BUY in profit
    await service.modifyOrder({ ticket: p.ticket, stopLoss: p.priceOpen });
  }
}
```

### 6) Risk/reward estimate before entry

```ts
const entry = (await service.getSymbolTick('EURUSD')).ask;
const risk   = await service.calculateProfit('BUY', 'EURUSD', 0.1, entry, entry - 0.0020); // -20 pips
const reward = await service.calculateProfit('BUY', 'EURUSD', 0.1, entry, entry + 0.0040); // +40 pips
console.log(`R:R ≈ 1:${(Math.abs(reward / risk)).toFixed(1)}`);
```

## 🔧 When to use which

- **Open a trade** → `placeOrder` (always check `retcode === 10009`).
- **Adjust SL/TP** → `modifyOrder`.
- **Close / partial-close** → `closeOrder`.
- **Dry-run before sending** → `checkOrder` (`returnedCode === 0`).
- **Size the trade** → `calculateMargin` / `calculateProfit`.

## 🎯 Summary

Trading methods replace protobuf request-building with plain objects and string actions, and decode the result into a typed `OrderResult` / `CloseResult` / `OrderCheckResult`. The retcode rule stays: **`10009` = DONE**, and the calculators (`calculateMargin` / `calculateProfit`) let you size and validate before committing.
