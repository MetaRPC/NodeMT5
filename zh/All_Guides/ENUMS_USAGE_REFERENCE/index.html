    Enums Usage Reference — Node¶

    The generated protobuf enums are plain JavaScript namespace objects: Namespace.CONSTANT → number. This page shows which namespace holds which enum, and how to use them at each layer.

    🧭 How protobuf enums look in Node¶

    import { TradingHelperPb } from '@metarpc/nodemt5';

TradingHelperPb.TMT5_ENUM_ORDER_TYPE.TMT5_ORDER_TYPE_BUY   // === 0 (a number)

    Each *Pb module is re-exported from the package. An enum is an object mapping names to numbers; you pass the value into a setter or compare it against a getter.

    📇 The enums you'll use most¶

    Enum Namespace Example value
    Order type TradingHelperPb.TMT5_ENUM_ORDER_TYPE TMT5_ORDER_TYPE_BUY (0)
    Account double property AccountInformationPb.AccountInfoDoublePropertyType ACCOUNT_BALANCE
    Account integer property AccountInformationPb.AccountInfoIntegerPropertyType ACCOUNT_LEVERAGE
    Account string property AccountInformationPb.AccountInfoStringPropertyType ACCOUNT_SERVER
    Symbol double property MarketInfoPb.SymbolInfoDoubleProperty SYMBOL_POINT, SYMBOL_TRADE_TICK_VALUE
    Symbol integer property MarketInfoPb.SymbolInfoIntegerProperty SYMBOL_DIGITS, SYMBOL_TRADE_STOPS_LEVEL
    Symbol string property MarketInfoPb.SymbolInfoStringProperty SYMBOL_DESCRIPTION, SYMBOL_CURRENCY_BASE
    Account trade mode AccountHelperPb.MrpcEnumAccountTradeMode MRPC_ACCOUNT_TRADE_MODE_DEMO
    Position type MarketInfoPb.BMT5_ENUM_POSITION_TYPE BMT5_POSITION_TYPE_BUY (0)
    Order state MarketInfoPb.BMT5_ENUM_ORDER_STATE —
    Day of week MarketInfoPb.BMT5_ENUM_DAY_OF_WEEK —

    Namespaces follow the proto service the message belongs to. When unsure, open the stub (package/*_pb.js) or use the Protobuf Inspector.

    🔽 Low level (MT5Account) — pass the enum directly¶

    import { MT5Account, AccountInformationPb, MarketInfoPb } from '@metarpc/nodemt5';

const bal = await account.accountInfoDouble(
  AccountInformationPb.AccountInfoDoublePropertyType.ACCOUNT_BALANCE,
);

const req = new MarketInfoPb.SymbolInfoIntegerRequest();
req.setSymbol('EURUSD');
req.setType(MarketInfoPb.SymbolInfoIntegerProperty.SYMBOL_DIGITS);
const digits = (await account.symbolInfoInteger(req)).getRequestedValue();

    🟦 Mid level (MT5Service) — same enum, plain call¶

    const digits = await service.getSymbolInteger('EURUSD', MarketInfoPb.SymbolInfoIntegerProperty.SYMBOL_DIGITS);
const point  = await service.getSymbolDouble('EURUSD', MarketInfoPb.SymbolInfoDoubleProperty.SYMBOL_POINT);
const server = await service.getAccountString(AccountInformationPb.AccountInfoStringPropertyType.ACCOUNT_SERVER);

    🟩 High level (MT5Sugar) — enums hidden¶

    The sugar layer wraps the common properties so you rarely touch an enum:

    const digits  = await sugar.getSymbolDigits('EURUSD');       // SYMBOL_DIGITS inside
const minStop = await sugar.getMinStopLevel('EURUSD');       // SYMBOL_TRADE_STOPS_LEVEL inside

    🛒 Order-type enum (trading)¶

    TMT5_ORDER_TYPE_BUY = 0   SELL = 1   BUY_LIMIT = 2   SELL_LIMIT = 3
BUY_STOP = 4   SELL_STOP = 5   BUY_STOP_LIMIT = 6   SELL_STOP_LIMIT = 7   CLOSE_BY = 8

    The friendly layers accept the string action instead — 'BUY', 'SELL_LIMIT', … — and map it to this enum for you (MT5Service.placeOrder, MT5Sugar.buyMarket).

    👤 Position-type enum¶

    BMT5_POSITION_TYPE_BUY = 0   BMT5_POSITION_TYPE_SELL = 1

    Position.type is this raw value: p.type === 0 is a long.

    ⚠️ Gotchas¶

    • Values are numbers, not strings — compare getter() === Namespace.CONST, don't compare names.
    • The Pb modules are typed any — TypeScript won't catch a wrong enum/namespace name; it fails at runtime. Verify names against the stubs (see Protobuf Inspector).
    • Namespace names can surprise you — e.g. symbol properties are SymbolInfoDoubleProperty (not SymbolInfoDouble), and the trade-mode enum is MrpcEnumAccountTradeMode with MRPC_-prefixed values.
